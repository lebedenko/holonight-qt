## Confirmed scope and reproductions

Haruna 1.8.1 SettingsWindow uses ItemDelegate with an Action carrying `icon.name`
and explicitly binds `highlighted` to its navigation current index. Its ShortcutsSettings
uses a reusable ListView ItemDelegate with a replaced RowLayout content item,
IconTitleSubtitle and KeySequenceItem; it does not bind highlighted or checked.
The provider currently drops navigation icons entirely, MenuItem only consumes
icon.source, and ItemDelegate renders ListView.isCurrentItem as selection.
MenuItem also reserves an icon column even in menus containing no icons.

Reproduce these independently with runtime-selected standard controls: Action named
icons, URL icons, a menu with changing visible items, and an unselected ListView
delegate with replaced content. Establish failing baseline assertions before repair.
Retain explicit navigation highlighting and keyboard focus. Tests must use an
isolated icon fixture rather than depending on the host's icon theme.

## Repair design

- Use existing HnIcon rendering for ItemDelegate and MenuItem, accepting theme names
  and URLs. Preserve ItemDelegate content replacement and existing public APIs.
- Menu owns a reactive scan of its items. Reserve the shared icon column only for
  visible icon-bearing entries, updating on insertion/removal/visibility/icon changes.
  Retain check column, submenu arrow and mirrored leading/trailing padding.
- ItemDelegate selected overlay follows explicit highlighted/checked only; ListView
  current-index bookkeeping alone does not imply application selection. Keep hover,
  press and visualFocus independently represented.

- R04 acceptance corrected on 2026-09-14: surround only the indicator track with
  a transparent pill outline, separated from its fill by a small gap. Exclude the
  label and thumb from outline geometry. Preserve sizing, mirroring and animation.
  The prior whole-widget implementation and regression are rejected historical work.
- F04 plain Button Tab → Space → Tab → Backtab retains owner, reason and visualFocus
  in both styles/scales. Test connection is now identified as an example; its real
  asynchronous enabled-state lifecycle still needs attribution. Do not claim repair.

No dependencies, third-party patches, runtime selector changes or palette policy changes.
