# UQC-204 — Shared form keyboard focus

State: Done locally (2026-09-11), pending canonical publication. Scope recorded
and made Ready before assignment; baseline verified before implementation.
Repository: holonight-qt. Published assignment baseline:

## Reproduction and scope

Settings: enter Weather City, edit text, then Tab through the form. First entry
into a ComboBox loses its visible keyboard indicator under HoloNight and Fusion.
AI: Context window SpinBox → invisible stop → Temperature SpinBox → Slider;
reverse traversal has no corresponding invisible stop. Repeating a complete
ComboBox cycle can restore its indicator. Disabled traversal is suspected only.
See the umbrella [canonical findings](../../../../docs/initiatives/unified-qtquick-controls/FINDINGS.md).

Repair only `qml/controls/HnSettingsRow.qml` and `HnFormField.qml`. A single
visible, enabled, tab-focusable loaded item is the scope's native subfocus target.
Compound layouts have no wrapper Tab stop; their eligible descendants participate
naturally. Missing, hidden, disabled and explicitly non-tab-focusable children
create no wrapper stop. Descendant entry must not imperatively redirect focus.
Preserve Tab/Backtab reasons, visualFocus, programmatic single-control entry,
FocusScope identity, properties, geometry and appearance. No public API, dependency,
application navigation links or global event handler is added.

Button ring loss after Space, checked-Switch contrast, VT-return delivery and
application slider sizing are separate findings, outside this repair.

## Verification contract

Extend the existing runtime-composite harness with both wrappers, first/repeated
forward/reverse traversal, the AI-shaped compound sequence, eligibility exclusions,
Loader replacement, direct descendant entry and programmatic scope entry. Assert
actual focus owner, reason, visualFocus and unchanged geometry. Run before the fix
and after under HoloNight/Fusion at DPR 1/1.25 in offscreen isolated processes.
Then run the provider suite, QML/import policy and installed-consumer checks.
No live desktop input automation. Manual acceptance stays pending until a fresh
kit receives the published provider; request only Settings/AI keyboard regression.

## Implementation and verification — 2026-09-11

Both wrappers derive their Tab eligibility from the loaded item's visibility,
enabled state and activeFocusOnTab. The Loader and its eligible item establish
native subfocus using declarative focus bindings. Removing onActiveFocusChanged
forwarding preserves keyboard reasons and avoids redirecting descendant entry.
Bindings also follow Loader replacement and dynamic eligibility changes. Layout,
public properties and FocusScope roots are unchanged.

`tests/test_form_focus.cpp` adds eight parameterized cases (four per wrapper) to
the existing runtime-composite binary. SpinBox's native editor is the expected
active item when Qt enters its focus scope; its Control keeps keyboard reason
and visualFocus. Tests assert actual ownership, not just activeFocus on ancestors.
TextField does not expose Control.visualFocus, so replacement uses a Button to
exercise that assertion without mistaking an absent property for a regression.
