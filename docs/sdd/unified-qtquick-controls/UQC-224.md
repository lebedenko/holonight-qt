## Contract

Inspect `providesPalette()` before any Qt Quick palette getter; read existing
palettes through the item/window private API. Keep QWidget palette handling and
skip unsupported QObject providers. Emit allocation state even without a palette;
preserve existing HN_PALETTE fields and timestamps, add activation/deactivation,
focus and hover records for correlation with existing scheme-transition records.
No singleton creation, palette assignment, inheritance refresh, deferred control
creation or live desktop interaction is permitted in observer sampling.

The actual shared library must be loaded in regression and audit processes.
Observer-on/off comparisons cover allocation, roles/masks, deferred controls,
transitions, rendered TextField fill, both styles/DPRs and dark/light construction
histories with two independent activation repeats. Test hover, re-resolution,
application events and overrides/reset separately. Keep the allocating Qt-boundary
case and provider-free/plugin-cleared comparisons distinctly labeled. Collection
failures must not be represented as behavior failures or passing evidence.

## Verification

Baseline observer binary preserved under umbrella `.cache/uqc224/`.
The actual pre-repair library allocates the root in both styles: 840 role
failures and four rendered TextField reversals per style at DPR 1.25. The new
allocation regression fails only with that library enabled; disabled cases pass.
The first collection failed on the sandbox D-Bus socket, retained separately;
retry outside that command sandbox kept offscreen isolation and passed collection.

After repair, 98 independent processes collect successfully and stability
assertion exits 0. All 49 real-library on/off pairs have equal named palettes,
resolve masks and TextField pixels, unallocated root palettes, and successful
shared-window dark/light/dark transitions. This includes 32 repeated activation
processes, 32 separate hover/resolve/application-event/enabled processes, 24
application/window/control override/reset processes and ten distinctly classified
plain-window/provider-free/plugin-cleared comparisons. Loaded observer and staged
provider/plugin origins and measured DPR are checked during collection.

The intentionally allocating light-history boundary still fails in both styles:
420 role differences and two TextField reversals each; assertion exits 1, while
collection exits 0. Its assertions were not weakened. The earlier UQC-223 matrix
and all released kits remain unchanged.

Registered observer checks now preload the actual MODULE instead of compiling
its source into the executable. They preserve application/widget and every
existing item palette/mask, reject allocation on previously unallocated
items/windows, reject unsupported QObject palette getters, and keep popup and
incomplete-control background implementations deferred. An initially completed
background fixture created itself even with the observer disabled; it was
replaced by an explicit beginCreate/completeCreate lifecycle fixture. This was
a test-fixture correction, not a product regression.

Narrow observer/window/Core/import-policy CTests: 13/13 pass. C++ clang-format,
Python syntax and Ruff, generated-fixture qmllint, REUSE (411/411) and whitespace
checks pass. No unrelated consumer suite or production changes.

HN_PALETTE retains timestamps and object identities for joining existing
scheme-transition timestamps; event records add names and beforeDelivery, and
sampling adds active/focus/hover state. No QML singleton lookup or application
state mutation is performed by the observer.
